Real-time fleet telemetry

Every vehicle.
Every second.
One live map.

Fleetwake takes in GPS, speed, fuel and engine readings from every vehicle you run, keeps each event in MongoDB, and pushes only what changed to every open dashboard over Socket.IO.

    Ingest

    01 / 04

    Every ping has a name, a number and a time.

    Each vehicle sends a small event about once a second. The ingest API checks it against a schema, limits how fast any one device can send, and drops repeats by vehicle and sequence number, so a flaky cellular link can't double-count a trip.

    {
  "vehicleId": "KA01-AB-4471",
  "seq":       88213,
  "ts":        "2026-11-13T06:41:07.412Z",
  "type":      "position",
  "lat": 12.97194, "lng": 77.59369,
  "speedKmh":  42.6, "fuelPct": 61, "engineC": 88
}

    Broadcast

    02 / 04

    Each screen hears only its own fleet.

    Dashboards join Socket.IO rooms for the fleets, regions or single vehicles they care about. The server gathers changes for 250 ms and sends one compact batch per room, with only the fields that moved.

    fleet:north-depot fleet:airport-shuttle vehicle:KA01-AB-4471
    • Batching250 ms window per room, deltas only
    • Client throttleMap and charts redraw at most 4 times a second
    • BackpressureSlow sockets get the latest state, not a growing queue

    Replay

    03 / 04

    This morning's route and this second's position, on one line.

    Open a vehicle and its history loads from a MongoDB time-series collection. Live events that arrive during the load are held, then merged by sequence number, so the trail has no gaps and no duplicate points.

    06:00 historyseq 88190 seamnow live

    Detect

    04 / 04

    Trouble shows up before the phone rings.

    Rules run on every event as it arrives. When one trips, an alert goes to the rooms watching that vehicle and is saved with the readings that caused it.

    OverspeedKA05-MN-2208
    94 km/hin a 60 km/h zone for 12 s, Outer Ring Road

    How it is built

    From the road to the screen in six steps.

    The whole path runs on the MERN stack with Socket.IO carrying live data. Vehicles are simulated by a Node script, so the platform can be load-tested without hardware.

    1. Vehicles

      Simulated trucks and vans drive real road routes and emit events.

      Node simulator

    2. Ingest API

      Validates each event and rate-limits each device.

      Express, Zod, rate limiter

    3. Dedupe and batch

      Drops repeats and late events by vehicle and sequence.

      In-memory buffer

    4. Store

      Writes events in bulk and keeps latest state per vehicle.

      MongoDB time-series

    5. Broadcast

      Sends deltas to the rooms that subscribed.

      Socket.IO rooms

    6. Dashboard

      Live map, charts, history and alerts.

      React, MapLibre, charts
